# 飞行模拟器 · Flight Simulator

一个**纯前端、零依赖安装、可离线运行**的 3D 飞行模拟器。双击 `index.html` 就能玩。

- 基于 Three.js（已内置到 `three.min.js`，不需要联网、不需要 npm install）
- 世界全部**程序化生成**：地形、跑道、机场建筑、植被、城镇、云、海面
- **简化但自洽的飞行动力学**：升力/阻力/推力/重力真实积分，迎角失速、过载限制、
  地面效应、风与湍流、地面滑跑与着陆判定
- **昼夜系统**：随时间变化的太阳位置、天空渐变、雾色、光照强度；黄昏有金色低角度光，
  夜晚有星空、跑道灯、城市灯火与机载着陆灯
- **三种玩法**：自由飞行 / 穿环计时 / 定点着陆（成绩用 localStorage 保存）
- **AI 交通**：两架飞机在机场左航线绕场飞行（用的是和玩家完全相同的物理模型与自动驾驶）
- 完整**平显 HUD**：俯仰梯、天地线、坡度指示、速度矢量、航路点指示、速度带、
  高度带、罗盘带、告警
- **座舱视角带三维仪表板**（空速 / 姿态 / 高度 / 升降率 / 转速 / 罗盘）
- **翼尖涡流**：2G 以上或大迎角时从翼尖拉出蒸汽尾迹；接地有扬尘、风向袋随风转动
- 程序合成**音效**（发动机、风噪、失速警告、接地、爆炸），无需任何音频素材

---

## 运行方式

**最简单**：直接双击 `index.html`（用 Chrome / Edge / Firefox 打开即可）。

**如果浏览器限制本地文件**，在目录下起一个静态服务器：

```bash
python -m http.server 8080
# 然后访问 http://localhost:8080
```

要求浏览器支持 WebGL。若打开后出现红色"运行出错"面板，通常是 WebGL 被禁用。

## 玩法

| 模式 | 规则 |
| --- | --- |
| **自由飞行** | 没有目标，随便飞。 |
| **穿环计时** | 12 个圆环绕岛一圈（约 12 km）。离地后自动开始计时，依次穿过所有圆环，最佳成绩自动保存。漏环会提示偏离距离，绕回去重穿即可。 |
| **定点着陆** | 跑道上画有靶心。按「距靶心距离」和「接地率」评分，满分 100；落在跑道外最高只给 35 分。 |

**风况**可选无风 / 微风 5 / 有风 9 / 大风 13 m/s。侧风会让机头指向与实际航迹
产生**偏流**（HUD 左下角显示风向、风速和偏流角），起降明显更难。飞行中按 `K` 随时切换。

**时刻**可选清晨 06:24 / 正午 12:30 / 黄昏 17:54 / 夜晚 22:00。
它决定太阳高度角与整套天空配色：

| 时刻 | 太阳高度 | 场景特征 |
| --- | --- | --- |
| 清晨 | 6.5° | 低角度暖光、长影子、跑道灯刚熄灭 |
| 正午 | 61.5° | 天顶蓝、影子最短、能见度最好 |
| 黄昏 | 1.6° | 地平线橙红、云镶暖边、跑道灯淡入 |
| 夜晚 | −53.7° | 星空、月面与月光、跑道灯与城市灯火全开、着陆灯照亮跑道 |

飞行中按 `T` 循环切换预设时刻，`[` `]` 每次微调半小时。夜晚飞行只能靠仪表、
跑道灯和着陆灯，是三种玩法之外另一个难度维度。

**AI 交通**：两架飞机在机场左航线（约 10 km 一圈）持续绕场，高度 240~420 m。
它们和玩家共用同一套飞行物理与自动驾驶控制律，所以压坡度、爬升、转弯都是真的在飞。
可以跟着它们飞编队，或者干脆拿来练空中拦截。

## 岛屿地标

六处地标，位置全部是**构建时从地形里搜出来的**（不写死坐标），所以换随机种子照样成立。
它们是目视导航的地标：飞的时候认准一个，比看 HUD 坐标直观得多。

| 地标 | 位置特征 | 说明 |
| --- | --- | --- |
| **山顶雷达站** | 全岛最高峰（约 500 m） | 半球天线罩 + 持续旋转的警戒雷达 + 三根通信塔，山顶有红色闪光障碍灯 |
| **海岸灯塔** | 东南海岸 | 红白相间塔身，夜里光束旋转扫射并有周期闪光 |
| **跨海大桥** | 机场东南约 1.7 km | 双塔斜拉桥，跨过一处约 190 m 宽的湖面窄口，桥塔顶有航空障碍灯 |
| **山谷大坝** | 机场西南约 2.8 km | 混凝土拱坝 + 泄洪闸 + 坝顶灯 + 下游厂房，上游是水库 |
| **风电场** | 西侧山脊（约 415 m） | 9 台风机，叶片持续转动 |
| **港口** | 东南海岸 | 折线防波堤、码头、三台门式起重机、两艘货轮 |

地标的**高度与尺寸是自适应的**：例如大坝的蓄水深由实际谷壁高度反推
（这片地形只有平原+环形山脊，没有河流切出的深谷，谷壁一般只高出河床 20~30 m），
水库长度则沿河谷实际往前走、走到谷壁兜不住水为止，保证水面不会露出山谷外。

## 机型

开始界面可以选四种机型，飞行中按 `Y` 循环切换（会复位到跑道）。
每个机型不只是换个外壳：**翼展、机长、翼面积、展弦比、质量、推力、失速速度、
滚转率、过载限制、抬前轮速度、螺旋桨效应全部不同**，气动参数直接覆盖到飞行模型上。

尺寸与气动都按**同级真机标定**，但不绑定具体型号：

| 机型 | 翼展 / 机长 | 质量 | 失速 | 最大平飞 | 爬升 | 特点 |
| --- | --- | --- | --- | --- | --- | --- |
| **教练机** | 10.7 / 6.1 m | 1157 kg | 96 km/h | 250 km/h | 3.7 m/s | 下单翼单发活塞，失速温和，推荐入门 |
| **特技机** | 8.0 / 6.9 m | 950 kg | 106 km/h | 389 km/h | 14.4 m/s | 滚转率 372°/s、过载 +10G，短翼滚转惯量小 |
| **喷气战斗机** | 8.1 / 14.3 m | 7200 kg | 258 km/h | 1186 km/h | 62 m/s | 33° 后掠翼双垂尾、双发加力；起降速度高 |
| **滑翔机** | 23.2 / 8.4 m | 850 kg | 92 km/h | 239 km/h | 4.1 m/s | 展弦比 44.8、滑翔比 53:1、下沉 0.45 m/s |

表里的数字是 `aircraft-types.js` 的 `perf()` 从气动参数**反推**出来的
（失速速度由 CLmax 和翼载算，最大平飞解「推力 = 阻力」，爬升率取单位剩余功率的
最大值）。开始界面上会把「同级真机参考值」和「本模拟器实测值」并排给出，
两者对不上的地方一目了然。

滑翔机收油门后下沉率只有 0.45 m/s——从 1000 m 高度可以滑翔 50 多公里，
足够绕岛一圈。喷气机反过来：失速速度 258 km/h，进近必须保持大速度。

## 起飞要领

1. 按住 `Shift` 把油门推到 100%，沿跑道加速。
2. 速度超过 **29 m/s** 后按住 `↓` 抬前轮，约 **33 m/s** 自然离地（约 120 km/h）。
   （喷气机要 **62 / 71 m/s**，滑翔机只要 **21 / 24 m/s**——各机型不同。）
3. 离地后松一点杆。记住：**俯仰控制速度，油门控制高度**。
4. 转弯要压坡度并带杆，否则会掉高度。60° 坡度需要 2G，拉到 2G 以上翼尖会拉出涡流。
5. 失速速度约 **26 m/s**（放襟翼后更低），HUD 速度带上的红线就是它。

## 降落

1. 五边对正跑道，`F` 放襟翼、`G` 放起落架。
2. 保持约 **40 m/s**，用 3° 下滑道（每 100 m 距离下降 5.5 m）。
3. 接地下降率要小于 **6.5 m/s**，坡度小于 22°，机头不能低于 −7°。
4. 接地后按 `Space` 刹车。

## 侧风起降

- HUD 左下角会显示「偏流」，是机头指向与实际航迹的夹角（12° 表示航迹比机头偏右 12°）。
- 保持航向要靠**压坡度**修正，不要一直蹬舵硬顶 —— 方向舵是用来协调转弯的。
  蹬反了会把侧滑越蹬越大，几秒内就会失控。
- 侧风大时晚一点抬前轮（跑道更长、离地速度更高），落地时带一点迎风侧的坡度。

`terrain.js`、`environment.js`、`physics.js` 都不依赖 DOM，
`world.js` 也只需要一个 canvas 桩就能在 Node 里跑，所以整套除了输入和渲染之外
都可以做数值回归。跑 `node checks.js` 会依次验证：

1. **几何**——四种机型每个操纵面的铰链线必须精确落在母面后缘上（实测误差 0）
2. **操纵**——配平是否改变配平速度、螺旋桨效应大小顺序、尾旋进入与改出
3. **动力**——气温对密度高度/滑跑距离的影响、混合比对功率的影响、四机型包线

失败会以非零退出码结束，方便接进任何 CI。

想自己写一段验证也很简单，整套动力学不需要浏览器：

```js
global.THREE = require('./three.min.js');
const { Terrain } = require('./js/terrain.js');
const { FlightModel } = require('./js/physics.js');

const terrain = new Terrain({}).generate();     // 约 60ms 生成整个地形
const m = new FlightModel();
m.reset(0, 430, 0, terrain);                    // 停在 36 号跑道南端
m.wind.set(12, 0, 0);                           // 加一股西风
for (let i = 0; i < 240 * 60; i++) {            // 模拟 60 秒
  m.step(1 / 240, { throttleUp: true, pitch: 0 }, terrain);
}
console.log(m.tas, m.agl, m.driftDeg, m.crashReason);
```

## 飞行模型说明

姿态用「**迎角指令**（俯仰）+ 速率指令（滚转/偏航）+ 气动稳定性」的混合模型，
轨迹则由升力、阻力、推力、重力真实积分得到，因此转弯率、爬升率、失速、
俯冲加速等宏观行为都是物理涌现的：

- 升力 `L = q·S·(CL0 + CLα·α)`，失速后平滑过渡到平板理论（升力骤降、阻力剧增）
- 阻力 `D = q·S·(CD0 + CL²/(π·AR·e) + 襟翼/起落架/侧滑/失速附加项)`
- **地面效应**：离地一个翼展内升力 +30%、诱导阻力 −42%，起飞离地和着陆拉平更"托得住"
- **过载限制器**：高速时自动限制可用迎角（+6g / −2.5g），全拉杆不会瞬间拉出十几 G
- **气动力用相对气流速度积分**（`v = 地速 − 风`），所以偏流、侧风修正、湍流颠簸
  都是同一条公式自然产生的，不需要任何特判
- 侧滑同时产生风标效应（偏航）与上反角效应（滚转），这一对耦合提供荷兰滚阻尼；
  两者调得过小会让飞机在侧风里持续摇摆

关键参数（`js/physics.js` 的 `DEFAULTS`）：质量 1150 kg、机翼面积 16.4 m²、
展弦比 7.2、最大推力 3200 N、失速速度约 26 m/s、最大平飞速度约 370 km/h、
滚转率上限 149°/s。

已用 Node 数值回归验证过的项目：起飞→巡航→转弯→失速→着陆全包线、
60° 坡度转弯率（实测 12.2°/s，理论 12.5°/s）、松杆回正稳定性、
四种坠毁判定（硬着陆 / 未放起落架 / 翼尖触地 / 迫降）、
侧风偏流（西风 12 m/s 实测 12.1°、20 m/s 实测 20.5°，理论 11.5° / 19.5°）、
强湍流下仍能保持航迹、昼夜配色在 0~24 时全程无异常（日出正东 0°、正午正南 62°、
日落正西）、AI 交通连续飞行 30 分钟 12 圈零坠毁且两机最小间距 1093 m、
六处地标构建 + 240 帧动画零异常、水库边界逐点采样确认水面完全被谷壁兜住
（上游远端 / 左岸 / 右岸三条边界全部高于水位）。

四个时段（清晨 6.4h / 正午 12.5h / 黄昏 17.9h / 夜晚 22h）与地标都做过无头浏览器
实机截图核对：夜晚能看到星空、跑道边灯与进近灯全亮；清晨是低角度暖光；
地标在对应位置正确落地。

**AI 自动驾驶**复用了玩家验证过的同一套控制律（航迹误差→目标坡度→压杆；
高度误差→目标升降率→杆量），但加了一条关键约束：杆量上限 0.55，
对应迎角约 0.19 rad，安全低于 0.26 的失速迎角。早期版本没有这个上限，
高度差一大就满拉杆，AI 直接拉失速进入持续盘旋下坠。

### 尾旋

尾旋不是脚本动画，而是从气动条件判出来的：**失速 + 明显舵量 + 有侧滑**才会进入。
只把杆拉到底不会甩起来——那样只会机头一低缓降（-2 m/s 左右）。

进入后机身绕**世界垂直轴**旋转，姿态锁在机头下俯约 37°、向自旋方向压 36° 坡度，
下降率维持在 1.5 倍失速速度。教练机实测自旋 138°/s、下降 36 m/s，
20 秒掉近 1000 m。改出靠推杆（迎角压到失速以下），实测 0.7 秒即可恢复。

这里用「姿态 + 速度直接给定」的运动学方式复现稳定尾旋，而不是完整的气动自旋——
后者需要左右机翼的非定常气动数据，用简化模型很容易变成没有意义的翻滚
（早期版本就出现过 144 rad/s 的翻滚，迎角一度到 122°）。

### 螺旋桨效应

扭矩反作用、滑流螺旋、P 因子三项，都按 `(1 - V/vRef)` 加权——低速大功率时最明显。
满油门低速飞 6 秒不修正的话，特技机左滚 12.4°、教练机 7.8°、滑翔机 1.6°，
喷气机没有螺旋桨所以是 0。起飞抬前轮那一下必须蹬舵修正。

顺带一个坑：测试里的**协调舵符号**必须和 physics.js 里风标项 `-beta*stabilityYaw`
一致（侧滑为正时蹬右舵）。早期回归脚本写成 `-beta`，等于跟风标稳定性对着干，
侧滑被推到 14°（特技机 47°），飞机直接爬不上去——那是测试的 bug，不是模型的。

### 大气与发动机

空气密度不是简单的指数衰减，而是「标准大气按气压高度算 + 按实际气温修正」：

```
rho = rho_ISA(h) × T_ISA(h) / T_actual(h)
```

修正项必须拿**该高度的 ISA 温度**当基准。早期版本拿海平面温度当基准，
结果 3000 m 上明明和 ISA 一样冷却被算成密度偏高，冷天反而飞不起来。

海平面气温按时刻给：14℃ 基准，15 点前后最热、凌晨最冷。这就是**密度高度**：

| 气温 | 空气密度 | 密度高度 | 起飞滑跑 | 180 s 后高度 |
| --- | --- | --- | --- | --- |
| 4℃（寒夜） | 98.9% | 112 m | 300 m | 447 m |
| 14℃（标准） | 95.6% | 467 m | 314 m | 431 m |
| 34℃（酷热） | 89.6% | 1127 m | 364 m | 387 m |

30℃ 的温差就让滑跑距离差 21%、爬升差 13%。

**混合比**只对活塞机有效。最佳值随密度高度下降（地面全富油、爬高要收稀），
偏离最佳值掉功率：1500 m 忘了收混合比大约掉 9% 功率，3000 m 掉 17%。
收到头（怠速关断）直接停车，推力归零。喷气机不受影响。

### 开关车与变距桨

活塞机有一套真实的开关车流程：

- **磁电机**（`B`）：双 → 左 → 关。关掉就停车，空中也一样。
- **混合比**（`PgUp`/`PgDn`）：收到底（怠速关断）也是停车。
- **起动机**（`X`）：按住才转，转够约 1.2 秒才点着。半途松开就是没点着。

停车后螺旋桨不会立刻停——空中会被气流带着「风车」转（教练机约 375 rpm），
地面则停住。**空中重新开车**是可行的：把磁电机打回双、按住起动机约 1.2 秒即可。

**变距桨**是可动的：每片桨叶挂在独立的 holder 上，桨叶角由物理量 `bladePitch` 驱动。
恒速桨的特性是低速大功率时桨叶变「粗」、高速巡航时变「细」：

| 工况 | 油门 | 空速 | 桨叶角 |
| --- | --- | --- | --- |
| 地面慢车 | 5% | 13 m/s | 7° |
| 起飞全功率 | 100% | 34 m/s | 28° |
| 爬升 | 100% | 42 m/s | 26° |
| 巡航 | 65% | 59 m/s | 16° |

喷气机没有磁电机、混合比和变距桨的概念，这些开关对它一律无效。

### 天气

开始界面可选**晴 / 雨 / 雪**（飞行中按 `O` 循环）。降水是围绕相机的一柱粒子
（低画质 1200 个、中 2400、高 4200），落到地面就回到顶部，出圈从对面绕回来，
并随风向漂移——雨点快而小、发蓝灰，雪片慢而大、纯白、更吃风。

| 天气 | 雾 near | 雾 far | 能见度 | 平飞最大速度 |
| --- | --- | --- | --- | --- |
| 晴 | 2600 m | 13500 m | 13.5 km | 56.7 m/s |
| 雨 | 424 m | 4084 m | 4.1 km | 55.1 m/s（−3.0%） |
| 雪 | 269 m | 3008 m | 3.0 km | 54.3 m/s（−4.3%） |

能见度是每帧跟着降水强度渐变走的，不是在切换天气时一次性设死——
否则过渡过程里雾的距离不会跟着变。

降水还会带来额外阻力（雨 +0.0048、雪 +0.0072 的 CD0 增量，约 CD0 的 16% / 24%），
平飞速度下降 3~4%，和真机 2~5% 的量级一致。

⚠️ 测这个效果时必须在**真正的平飞状态**下比。早先的回归脚本直接给 `pitch: 0`
让飞机自己加速，那是在俯冲，三种天气的速度几乎一模一样，看不出任何差别。

### 起落架舱门

可收放起落架的机型（喷气机）带轮舱盖：铰链在舱门的纵向外侧边，
收起落架时贴着机腹闭合（`rotation.x = 0`），放起落架时向外张开 83°。

### 机翼后掠角的符号坑

`taperedWing(rootChord, tipChord, span, thick, sweep, ...)` 里的 `sweep` 是**把翼尖整个沿 z 平移**的量。
机头朝 **−Z**，所以 `sweep > 0` 才是后掠，负值是前掠。

但前缘的实际后掠角还要叠加弦长收缩：

```
tan(前缘后掠) = (sweep + (rootChord - tipChord) / 2) / span
```

所以即使 `sweep` 是负的，只要弦长收缩够大，前缘仍可能是后掠的——
教练机 `sweep = −0.28`，靠 0.475 的弦长收缩，前缘实际还是后掠 2.2°，
所以一直没暴露问题。喷气机写 `sweep = −1.95` 就直接成了前掠翼。

现在四种机型的每个翼面都跑一遍角度检查：

| 机型 | 主翼前缘 | 主翼后缘 | 平尾前缘 | 垂尾前缘 |
| --- | --- | --- | --- | --- |
| 教练机 | 后掠 2.2° | 前掠 8.3° | 后掠 9.1° | 后掠 25.3° |
| 特技机 | 后掠 7.2° | 前掠 5.3° | 后掠 10.4° | 后掠 24.4° |
| 喷气战斗机 | 后掠 33.0° | 后掠 4.0° | 后掠 35.0° | 后掠 33.0° |
| 滑翔机 | 后掠 1.9° | 前掠 1.9° | 后掠 15.2° | 后掠 30.8° |

轻机那种「前缘近平直、后缘前掠」是正常的锥形翼平面形状（塞斯纳就是这样），
不是错误；真正要避免的是前缘前掠。

### 操纵面是怎么贴上去的

副翼 / 升降舵 / 方向舵不是「平放的盒子」，而是从母面后缘切下来的一块，
必须跟着母面的锥度、后掠和上反角走。做法是：

1. **母面留缺口**：主翼/平尾/垂尾按展向切成三段，在操纵面占用的区段把后缘按
   弦向比例让出来（副翼让 28%，升降舵和方向舵让 38%）。不这么做的话母面是个
   实心棱柱，操纵面会整块埋在里面看不见。
2. **操纵面填缺口**：用同一套母面参数算出铰链线和后缘，生成一块正好填满缺口的
   梯形翼面，所以两者共享同一条边界，既不悬空也不重叠。
3. **绕真实铰链线偏转**：枢轴上存着铰链方向的基准四元数，偏转时 `base × Δ`，
   这样即使铰链有上反角（副翼 5°）或是垂直的（方向舵）也能精确绕铰链转。

早期版本用固定位置的盒子充当操纵面，量出来的偏差是：副翼外端比机翼后缘
**低了 0.40 m、靠后 0.93 m**；升降舵和方向舵同理。现在用包围盒回归验证：
副翼完全包含在主翼内，升降舵前缘 z=2.09 与平尾缺口后缘 2.09 精确重合。

地形用「**径向剖面 + 噪声扰动**」而不是纯噪声：机场所在平原保证在半径
700 m 内绝对水平（跑道误差 0 米），2~5 km 处是环形山地（峰值 330~520 m），
再往外是海岸与海面。任何随机种子下这个结构都成立。

穿环赛道的 12 个圆环高度是**逐段采样地形自动定的**，保证整条走廊净空 ≥ 95 m，
最大爬升梯度只有 8.8%，不用背地图也飞得下来。AI 航线同样按地形抬高，
保证相对地形净空 ≥ 246 m。

## 性能

开始界面可选三档画质：

| 画质 | 树木 | 云 | 阴影贴图 |
| --- | --- | --- | --- |
| 低 | 900 | 110 | 1024 |
| 中 | 2200 | 220 | 2048 |
| 高 | 3600 | 340 | 2048 |

地形固定 300×300 网格（约 18 万三角形，单次绘制调用），生成耗时约 60 ms 并带进度条。
植被与城镇用 `InstancedMesh`，各只占 1~2 次绘制调用。翼尖涡流是两条动态更新的
面向相机的带子；座舱仪表板是一张 640×200 的 canvas 贴图，只在座舱视角下按 28 Hz 重绘。
夜空加了约 1400 颗星、60 个跑道灯辉光点和约 700 个城市窗口灯，都是单个 `Points`，
加起来只占 3 次绘制调用。太阳和月亮是两盏平行光交叉淡入（只有太阳投影），
两盏灯始终留在场景里只调强度——增删灯光会触发着色器重编译，切换时刻时会卡一下。
